## Remaining production considerations

- **Public signup and mail abuse:** there is no application rate limit on
  authentication, provider tests or manual mail sends. A public deployment should
  add account admission and request limits before sharing server-funded APIs/SMTP
  with untrusted users.
- **Configurable outbound endpoints:** custom LLM and SearXNG URLs intentionally
  support local services. For untrusted public accounts, restrict destinations
  and outbound network access; credential isolation does not prevent arbitrary
  outbound requests to reachable internal endpoints.
- **Scheduled delivery:** daily/weekly cadence uses attempt timestamps, SMTP
  acceptance is not inbox delivery, and failed delivery has no independent retry
  queue. Multiple backend replicas require coordination; startup reconciliation
  assumes one backend instance.
- **Dependency maintenance:** images such as `nginx:alpine` and
  `searxng:latest` are mutable, and no image vulnerability audit was run. Pin and
  audit release images when preparing a production rollout.
